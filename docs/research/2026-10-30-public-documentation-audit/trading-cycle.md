## Ranked findings

1. **High: sentiment guidance hides automatic provider-billed event updates.** Reader `src/content/docs/trading-cycle/entities/sentiment-reports.md:59` describes manual refresh and renewal by a running session, but omits automatic post-event updates of active, nonexpired packages even without a session. A user following this could leave a package active expecting only manual provider usage. Current `cortiq-app/docs/reference/sentiment-reports.md:9-44` describes host-wide maintenance, High-impact events, a 30-minute default delay, bounded retries and unchanged original expiry. Concrete UI: `cortiq-app/Cortiq.BlazorApp/Components/Pages/SentimentPackageDetailPage.razor:103-104` explicitly discloses this behavior and billing; `:72` renders update status/history. Smallest correction: add the event update behavior, host-running requirement, configurable delay, billing and preserved expiry to the refresh paragraph; distinguish event updates from a new full generation.

2. **High: sentiment source and date descriptions are now factually reversed.** Reader `entities/sentiment-reports.md:49` says sources support only the whole report, and `:51` says publication dates are not recorded. Current `cortiq-app/Cortiq.BlazorApp/Components/Shared/SentimentReportView.razor:129-145` renders claim-specific sources, excerpts, `PublishedAtUtc` and `AsOfUtc`, with truthful legacy fallback. Current owner `cortiq-app/docs/reference/sentiment-reports.md:89-95` confirms available publication/event/data dates are preserved and new sources link to claims. `:173-195` documents exact evidence excerpts and independent analytical review. Smallest correction: explain per-claim evidence, dates where supplied, unknown missing dates, the legacy report-level fallback, and independent review. Also `reader :15` overstates an observed-query prerequisite: current owner `:125-128` permits providers without query telemetry if that absence is disclosed; retain completed search, observed sources and substantive evidence requirements rather than a mandatory query record.

Current `cortiq-app/docs/reference/continuous-assessment.md:137-140,191-234` describes one assessment family, independently retained understanding and optional opportunities; no global plan is required for assessment or entry. Concrete source `cortiq-app/Cortiq.Business/Services/Autonomy/Packets/AutonomousPacketCycleRunner.Assessment.cs:18-26,60-100` routes model work through the assessment compiler/application. Smallest correction: replace that subsection with Establish/Continue/Refresh view, retained market understanding, opportunities and meaningful local wakes. Do not claim thinking effort has become universally identical: Auto still maps captured task kinds through `Services/Autonomy/Tools/NativeReasoningEffort.cs:29-39`; remove obsolete plan-stage terminology without inventing a new effort guarantee.
